# M11 计划:项目收尾

**状态:所有者 2026-11-13 批准。**过程记在 docs/m11-进度.md。本计划不打开任何测试集,不训练,不运行模型,不改动被评测的系统,云端 API 花费为 0。

## Context

- **起因**:M10 之后,所有者问整个项目是否已经全部完成。一次核查覆盖了 70 项:未完成的 41 项由独立的核验者逐条反驳,另有一名批评者专找遗漏。结论是研究线与产品都已完成,或已由所有者的决定收口,剩下的是收尾。
- **所有者的选择**:
  1. Claude Code 自己的收尾现在做:备份只在本机的新运行记录;改正 README 不准确的地方,并说明 M5 预登记的抬头;重新导出,由所有者发布。
  2. 补上 M7 预登记承诺而没有报告的描述项,以及 final 成功率的 Wilson 95% 区间;算不出的写明原因。
  3. 下面三项不做,写进「局限」:final 补跑 BFCL、补齐 B2 的端到端参照、「只用真实思考」的消融。
  4. 先列清单再清理:旧的辅助工作区、私有远端的旧分支、底座对比中落选候选的权重。
- **边界**:被评测的系统不变;`results/numbers.json` 只增不改,旧键与旧值逐字不变;测试结果文件只经仓库自己的报告脚本读取。

## 做法

### 1. 报告补项(`src/research_agent/eval/`,先写测试)
- **Wilson 区间**:`metrics.wilson_interval`,只用标准库,z 取 1.959964。测试包括预登记的两个算例(270/300 → [86.1%, 92.9%],135/150 → [84.2%, 93.8%])和边界情形。报告给每个测试结果文件加 `success_wilson` 键,成功数由成功率与题数还原,还原不出整数就拒绝。
- **B2 各思考模式的回合数**:报告读出结果文件中的 `modes`。
- **ACEBench 各层差**:同时含 B0 与 FT 的文件,按每层的正确数与题数精确算差。M7 的层均差必须等于已报告的 −3.96。
- **ACEBench 生成长度**:新脚本从服务器日志读出每次请求生成的 token 数,写入 `results/lengths-acebench-m7.json`。这个数是思考与回答的合计,日志不把两者分开;运行脚本自己的探针请求剔除。日志有任何异常,脚本即失败。
- **底座对比**:报告登记 `results/bakeoff-m7.json`;新增 `results/bakeoff-descriptive-m7.json`,收录两个消融与胜者试训适配器的保真核对。重算的值与已登记的值不符就拒绝。
- 每次重建 `numbers.json` 后,核对旧键与旧值逐字不变。
