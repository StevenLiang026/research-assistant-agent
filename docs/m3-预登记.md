## 主要比较(预先登记的检验族)

主要终点:单步决策成功率(`data/eval/test.jsonl` 全部 300 道)。

| 编号 | 比较 | 在 M3 中 |
|---|---|---|
| 1 | FT 对 B0 | 检验 |
| 2 | FT 对 B1 | 检验 |
| 3 | FT 对 B4 | 检验 |
| 4 | FT+R 对 B2 | M4 才有 FT+R,M3 中按 $p = 1$ 计入 |

- 效应量:成功率之差 $\hat\Delta = \hat p_a - \hat p_b$。
- 区间:配对 bootstrap 95% 区间(10,000 次重抽样,种子 42);另报聚类 bootstrap 区间(草拟题按模板族成簇,每道手写题自成一簇)。区间不做多重校正。
- 检验:配对的精确 McNemar 检验(只用不一致对)。
- 多重比较:对上表 4 个 $p$ 值做 Holm 校正,显著性水平 $\alpha = 0.05$。

描述性结果(不做检验):按类别(调用、追问、直接回答)、语言、草拟与手写子集的成功率;端到端任务成功率(60 个);B2 的结果与其思考模式、非思考模式的题数;时延 p50 与 p95、显存、成本(实际付费与按列表价折算)。

## 选检查点规则(在开发集上执行,已完成)

规则:开发集单步成功率最高的检查点,平局取更后的步数。结果:FT 选第 1,668 步(最后一个检查点),成功率 66.0%(99/150);B4 选第 417 步,成功率 38.7%(58/150),此后逐步下降,第 1,112 步为 28.7%(43/150)。完整记录在 `results/checkpoint-selection-ft.json` 与 `results/checkpoint-selection-b4.json`。所选检查点的开发集分数经过挑选,有乐观偏差,只作选择依据,不作结论。

## 判分口径

- 单步:沿用 M2 的指标(工具名与参数逐项比对,编号与日期等按 M2 的规范化);`write_note` 的自由文本参数不按字面比对,只比 `arxiv_id` 与 `mode`,且调用须通过执行器的参数校验;`ask_clarification` 的问句同样豁免。
- 端到端:沿用 M2 的口径(提交 `01b8d8f`):轨迹校验、状态、所用工具、笔记、引用编号,以及笔记证据须是本轮此前取回的该论文原文的连续片段。

## 打开测试集的流程

1. 预检(读测试集之前,任一项不满足即拒绝,不打开、不启动):配置已提交且工作区干净;适配器 GGUF 的 SHA-256 与配置一致且是选点文件选中的那个;B1 示例块哈希一致;M3 预算能容纳 B2 的上限;两把锁校验通过;两份访问日志都还有剩余次数;显卡空闲;端口空闲;没有缺完成标记的打开。
2. `--dry-run`:同样的预检,外加每个系统在开发集上跑一道单步题与一个端到端任务。
3. 打开:每个测试集恰好打开一次;题目只在内存中;同一会话依次运行 FT、B0、B1(FT 服务器),B4(B4 服务器),B2;同一进程内打分并写结果、比较与资源文件,最后写完成标记。
4. 会话中途失败不续跑、不补跑:该次打开作废,由所有者用 `--abandon "<理由>"` 记录决定后才能再次打开(共 3 次)。

## 已知限制

- 选中检查点的开发集分数有选择偏差;测试集分数不受此影响。
- B2 在草拟题上的金标准就是它当时的回答,且由响应缓存返回,草拟题上的 B2 分数不说明能力。
- 时延与显存受笔记本 GPU 热状态影响(训练期间温度封顶 88.5 °C),只作量级参考。
- 全精度(HF bf16)与 llama.cpp Q8_0 的差异单独报告(`results/backend-comparison-*.json`),主要比较一律用 llama.cpp Q8_0。
- 开发集上 4 槽服务器的记录依赖运行顺序(M2 的 B1 单步、阶段 3 的 FT 端到端);与测试同条件的开发集结果是单槽的那一组(`results/dev-b1-1slot.json`、`results/dev-e2e-*-1slot.json`,其余系统的单步记录在单槽下逐字节不变)。

## 修订(第一次打开之前)
