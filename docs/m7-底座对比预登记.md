## 共同条件

**数据**
- 文件:`data/raw/public/*.jsonl`、`data/raw/synth/synth-m6.jsonl`,重叠报告 `data/synth/benchmark-overlap-m6-all.json`,与 FT2 相同。
- 会思考的候选另加两份思考侧车:老师原有的思考,以及补写的思考。
- 有思考的样本按 THINK 训练,其余按 NO_THINK:空思考块放进提示,不计损失。
- THINK 样本超长时退回 NO_THINK。

**训练**
- QLoRA:NF4,paged_adamw_8bit。
- 超参数:r 16,alpha 32,dropout 0.05,学习率 1e-4,batch 1 × 梯度累积 16。
- 日程:余弦,3% 预热,种子 42,data_seed 42;全程周期 2,192 步(2 轮),到第 274 步停止。
- 最大长度 5,120。C1 用 4,096,与 G2 相同;在 Qwen 分词下,没有任何 NO_THINK 样本超过 4,090,所以两种长度的数据相同。
- LoRA 目标:解码层里所有 llama.cpp 会应用的线性投影,按家族登记,由冒烟 S6 核验。

**评测**
- 开发集:`data/eval/dev.jsonl`,150 题,其中草拟 103、手写 47。
- 服务器:llama-server 单槽,`cache_prompt false`;带信号。

**解码**
- 不思考的家族:贪心。
- 会思考的家族:
  - 用厂商推荐的采样参数;
  - 种子由基种子、提示 id、阶段、样本号散列得出;三次运行的基种子分别是 0、1、2;
  - 另跑一次贪心思考。
- 混合家族:另跑一次不思考贪心。
- 推理预算 R:取 1,024 与「该家族分词下训练思考长度 p99 向上取整到 256」中的较大者,上限 2,048。R 在冒烟 S2 时由训练数据算出,评测前写进记录。

| 步 | 通过标准 |

| S3 | 用最长样本跑 20 步,峰值保留显存 ≤ 7.0 GB |

**其他规定**
- **修复时限:**任一步不过且 2 小时内修不好,即判为不具资格,写明原因。
- **时长资格:**FT3 预计时长须 ≤ 60 小时,算法如下:
  - token 数 = 该候选 dry run 的每轮 token 数 × 1.45 × 2 轮(1.45 是新增数据带来的增量);
  - 吞吐 = 试训第 100–274 步 tok/s 的中位数;
  - 预计时长 = token 数 ÷ 吞吐。
- **C1 的豁免:**C1 与 G2 同架构、同分词器,G2 已验证全流程,所以免去 S0–S4;S5、S6 在工具就绪后补跑,只作记录。

## 主分与胜者

**主分 P**
- 不思考的家族:贪心运行的成功数。
- 会思考的家族:基种子 0、1、2 三次运行成功数的平均。

**胜者**:P 最高者胜。
1. 前两名相差 ≤ 3 题时,两者都按同一日程续训到第 548 步,各评 3 个种子(不思考的家族评贪心),再比 P。
2. 续训后仍相差 ≤ 3 题,比手写题的成功数(会思考的家族取三次平均)。
3. 仍然相同,比 FT3 预计时长,短者胜。

**C0**
- 参与比较,P = 107。
- 需要续训时,从 G2 的 `runs/train/ft3-pilot/trainer/checkpoint-274` 续训,优化器状态已保存。

**全部候选都不具资格时**:FT3 用 C0 的配置。

**FT3 用哪种模式**
- 会思考的家族胜出:用思考模式。
- 例外:混合家族的不思考贪心成功数比思考均值多 ≥ 5 题时,改用不思考。

## 只报告、不参与判定

- 贪心思考的成绩;
- 混合家族的不思考成绩;
- 未训练底座 b0 的成绩;
- 草拟与手写两个子集的成绩,以及各题型的成绩;
- 思考长度的中位数与 p95,强制收尾率,用时;
- C0 与 FT2@274(100/150)作参照。

## 不允许

- 看到任一候选的分数后,修改数据、日程、R、种子或解码设置。
- 因为分数而排除候选。排除只能出于冒烟或时长资格。
- 用其他种子重跑某个候选,再挑最好的一次。
- 对某个候选单独排查失败题,并据此改动它的配置。

## 修订 1(2026-10-26,所有者决定):S6 只报告,不作资格

**依据**:按上文的写法,S6 对任何候选都不可通过(数据在 `runs/bakeoff/m7/<候选>/smoke.json`,分析在 `docs/m7-进度.md` 10-26 一节)。
- 无 LoRA 时,HF(NF4)与 llama.cpp(Q8_0)的 top-1 一致率是 0.95–0.97。
- 要让随机 LoRA 改变至少 30% 的 HF top-1,强度要加到基座权重范数的 0.56–2.0 倍。
- 在这个强度下,模型被推进混沌区。C2、C3、C8 每一组的一致率都落在 0.00–0.79,并随改变比例单调下降(C2 gate_proj:改变 100%,一致率 0.000)。
- 「改变 ≥ 30%」与「一致率 ≥ 0.90」两个条件,对随机 LoRA 不能同时成立。
- C2 的结构就是 M3–M6 一直在 llama.cpp 上运行 LoRA 的 Qwen3,它在 llama.cpp 上的开发集分数 111.3,远高于底座的 86。

**决定**:所有者 10-26 选「只报告,不作资格」。
- 资格改为 S0–S5 加 FT3 预计时长 ≤ 60 小时。
- S6 照跑照记录(配置里 C2–C9 的 `record_only` 加 `S6`;C1 原本就是 `S5`、`S6`),不再构成失格理由,也不再等它。
- 选底座用的 P 本来就是在 llama.cpp 上带试训适配器测的,适配器若有哪一组没被 llama.cpp 应用,会直接压低 P。
- 胜者另做一项只报告的核对:用它的试训适配器(检查点 274,续训了就用 548),在 S6 的 20 条序列上比较 HF(NF4)与 llama.cpp(Q8_0)的 top-1 一致率,与无适配器时的一致率并列报告。

**时点与公平性**:
- 决定做出时,C2、C3 的 P 已知;C4、C5 的 GGUF 尚未转换,C8 的评测正在进行。
- S6 对所有候选同样不可通过,这次修订不偏向任何候选,其余规则不变。
- 配置文件 `configs/bakeoff-m7.json` 的 SHA-256 由 `171ffaf2…` 变为 `50333c84…`。

**依据**:计划 `docs/m7-计划.md` 的砍线第 2 条写明,第 ④ 波整体落后超过一天时跳过这一波。10-26 进度落后已超过一天(10-21 至 10-26 的工作暂停、10-22 的非正常关机),C6、C9、C7 按此跳过。这是计划已有的条款,不改动本文的任何规则。

**时点与公平性**:

## 修订 3(2026-10-27,任何混合家族的第 548 步分数出现之前)

**一、续训后,混合家族的模式按续训那一步判定**

- **依据**:上文「FT3 用哪种模式」写明,混合家族胜出时默认思考,只有它的不思考贪心比思考均值多 ≥ 5 题才改用不思考;没写胜负在续训后才定时用哪一步的数字。汇总代码原来一律用第 274 步。10-27 的对抗审查指出这是未写明的选择。
- **决定**:胜负依据来自续训时(第 548 步的 P、第 548 步的手写题,或两者都续训后的 FT3 时长),模式也用第 548 步的数字,即第 548 步的不思考贪心对第 548 步三个种子的均值。未续训就定胜负时,仍用第 274 步。
- **理由**:决定胜负与决定模式用同一个训练状态;续训时本来就评了不思考贪心。
- **时点**:写定时 C3 尚未续训,任何混合家族都没有第 548 步的分数;C3 在第 274 步的差是 4.67 题(不思考 114 对思考均值 109.33)。C2 是只思考家族,不受影响。
- **实现**:混合家族的续训评测缺不思考贪心时,该候选记为不完整、裁决等待,与第 274 步相同。

**二、两处实现修正,不改规则**

1. **C2 的 S0–S3 从未运行。** C2 的试训(10-19 至 10-20)由早先的启动器直接运行,只做了预检、试训与评测;10-21 补跑冒烟时只跑了 S4–S6,S4 因缺输入(S3 写出的冒烟适配器)而被记为失败。闸门因此把 C2 判为不具资格,汇总随之把它从排名中拿掉。
   - 这是工具的调度缺口,不是 C2 的问题。
   - 处置:续训结束、显卡空闲后,在出裁决之前补跑 C2 的 S0–S5,资格照本文的冒烟标准判定。
   - 若某一步确实不过,照「一步不过且 2 小时内修不好即排除」处理。
2. **冒烟状态的口径。** 一步因其前置步骤(S4 需要 S3,S5 需要 S4)没有通过而失败时,记为阻塞(裁决等待前置步骤),不再算作失格理由;前置步骤通过后仍失败的,照旧是失格理由。

**时点与公平性**:写定时 C2、C3、C4、C8 在第 274 步的 P 已知,C5 正在评测,C2 第 548 步的 P 已知(115.67),C3 尚未续训。这三项都不依据任何候选的分数:第一项对所有混合家族同样适用;第二项只补跑资格检查,不改资格标准。
