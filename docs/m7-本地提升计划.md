## Context

**起因。**10-29 所有者改了目标:本地模型单独做到尽可能好(预登记修订 1),路由 R3 作废。现有基线是 FT3(第 1635 步,贪心思考,推理预算 R = 1280):
- dev ∪ dev-v2:222/276(80.4%);
- 留出集 dev-ext ∪ dev-v2-ext:134/155(86.5%)。

**错题分析**(分 5 项,每项都有独立复核,计数全部复现):
- **54 道失败的构成**:模型错误约 36 道;金标准约定问题约 14 道,来自 dev-v2 草拟金标准沿用的 flash 随手设定;指令有歧义约 4 道。
- **系统性的模型错误有两类**:
  - 中文主题词译不成标准英文检索词,10 道。从零翻译时,「测试时扩展」0/55 次译对。
  - 瞬时错误后改写检索词,7 道。原因是训练目标里有 44% 本身就不是原样重试。
- 其余模型错误多数不稳定:同一题采样几次,能对其中一部分。
- **思考预算不是杠杆**:强制收尾只占 2.2%。
- **置信信号**:对数概率无效(AUROC 0.56);多次采样的一致性有效(0.90)。

**种子 2–4 已跑完**(10-29)。第 1635 步 5 个种子的单次成功数为 220、224、222、224、217。5 个种子投票、贪心只用来破平局,得 237.3/276:
- 比贪心多 +15.3,配对 95% 区间 [+7.8, +23.7];
- 高于分析事先预测的 227.5–232.7。

**所有者 10-29 的两项决定:**
1. **评分加对称归一,作主分;原评分并列报告。**三条归一是:
   - S1:date_to 等于当天,视同省略;
   - S2:检索词里的连字符视同空格;
   - S3:请求没给数量时,top_k、limit、max_chars 取缺省值或金标准值都算对。
2. **本地主系统可以包含三种推理期手段**:投票或检查点集成、运行时规则、外部中英术语表。纯模型单次贪心的成绩并列报告。

**独立审查之后的修订**(审查共 12 条,已并入本文):

**预期产出:**

### WP1 评分模式(S1、S2、S3)

**`src/research_agent/eval/metrics.py`**:`score_items` 与 `score_item` 加 `scorer` 参数。缺省为现行口径,输出逐字节不变。`normalized` 模式按三条归一:
- **S1**:
  - 当天日期从首条系统消息「今天是 {today}」取(`agent/prompts.py:16`),一路传进 `_Call` 与 `_expected_calls`;取不到时 S1 不生效。
  - 归一时,两侧 `date_to == today` 的键都删掉。键的有无参与比较,见 `_args_match`。
- **S2**:
  - NFKC 之后,把 U+002D、U+2010、U+2011、U+2012、U+2013 视同空格,再合并空白。
  - 作用于四处:必含词的提取、包含判断、相等比较的回退,以及 slots 里的检索词。
  - `query_strict` 保持字面。
- **S3**:
  - 适用条件:`slots` 里没有 `count`,且金标准的取值没有出现在请求文本里。
  - 此时 `search_notes.top_k`、`list_notes.limit`、`fetch_fulltext.max_chars` 等于缺省值或金标准值都算对。
  - 采用你批准的「缺省或金标准」,不用分析里「任何值都算对」的写法。两者在贪心上结果相同,在采样上不同;以后的数字一律用实现后的规则,不为凑分析的数改规则。
  - `search_arxiv.max_results` 不在批准范围内,不动。

**口径透传:**
- `scripts/score.py` 加 `--scorer`;`select_checkpoint.py` 透传。
- `run_test.py` 在 `OPTIONAL` 中加 `scorer`,`single_step()` 同时输出两种口径。
- `report.py` 按口径出数;缺省口径的键不变,`numbers.json` 重建后逐字节不变。

**测试:**每条归一写正反例,包括手写题请求里写明了字数的情形。

### WP2 投票(`--votes K`,K = 5)

**模型包装:**新文件 `src/research_agent/eval/vote.py`,其中 `VotedModel` 包住 1 个贪心 `LocalModel` 与 K 个采样 `LocalModel`。
- 第 k 个样本用基种子 k、样本号 0。这样在线投票与已有的 `--seed k` 运行逐字节一致。

**答案键,分两步实现:**
1. **复现模式**:与分析脚本 `voting_analysis.py` 的键逐项相同,包括:
   - 非 ok 记录记为 `STATUS:x`;
   - 参数无法解析记为 `!json:<原文>`;
   - write_note 保留未知参数,并标出 schema 拒收的自由文本。

   先逐题复现分析的胜出类,以及「类内取最小种子」时的 238。
2. **正式模式**:在复现模式的键上再加三项:
   - S1(当天的 date_to 删去);
   - S2(检索词连字符视同空格);
   - 「所有 arXiv 编号都在历史中出现」的标志。

**规则 A(定票):**
- 失败的候选(非 ok、JSON 坏)不参与投票;全部失败时输出贪心的记录。
- K 个样本中得票最多的类胜出。
- 平局取含贪心答案的类;贪心不在平局各类中时,取最小样本号所在的类。
- 胜出类的代表答案取类内样本号最小者。
- 运行时规则(WP3)先作用于每个候选,再投票。

**记录:**
- `AssistantTurn` 加 `votes` 字段,内容包括各类计数、选中的类与各候选的键;写进单步记录与端到端的每一步。
- 用量与时延按 K + 1 次请求累计。

**入口:**
- `scripts/run_eval.py` 与 `scripts/run_e2e.py` 加 `--votes K`。
- `GenerationSettings.record()` 只在投票时加 `votes` 键,旧清单逐字节不变。

**验收:**
- 开发集上只用种子 s0–s4 核对;
- 抽 20 题跑在线投票,与离线结果逐题一致;
- 正式模式在两种评分下的整数成功数写入修订 2。

### WP3 运行时规则

**位置:**做成模型包装 `RuledModel`,使端到端的 `check_step` 仍会校验改写后的调用。
- 规则看完整历史:单步取题目的全部消息,端到端取转录记录,不用压缩后的上下文。
- 包装放在任何路由包装之内。

**`transient_retry`:**
- 上一步的工具结果中有 RATE_LIMITED 或 UPSTREAM_ERROR 时,本步只原样重发失败的调用:失败几个就重发几个,成功的不重发。
- 按历史统计该调用已执行的次数;达到端到端上限 `MAX_RUNS_PER_CALL = 2` 时不触发。
- 端到端的打开不注入故障(`run_test` 不传故障率),这条规则主要作用于单步。

**`id_repair`:**
- 历史编号集合用 `metrics.arxiv_ids` 对全部历史计算,与评分的 `ids_grounded` 同一口径。
- 调用参数里的编号不在集合中,而集合里恰有一个编号的序号部分与它相同时,替换成该编号。

**记录:**写入 `rules` 字段(规则名、改前、改后);信号仍描述原答案。

**验收:**
- 把包装作用于已存的贪心上下文,输出与分析的离线函数逐字节一致;
- dev ∪ dev-v2 上修 8 道,改坏 0 道;
- 单元测试覆盖三种情形:混合轮、执行次数达到上限、序号对应多个编号。

**过滤规则只在训练数据上调**(例如中文最短长度、通用词停用表),不看 dev。调整的依据是:对训练集里的中文请求注出的英文,与 teacher 实际使用的检索词吻合的比例。

**注释方式:**
- 对最新一条用户消息做最长匹配,不重叠,至多 5 条。
- 在系统消息末尾追加一行,形如「术语对照:混合专家 = mixture of experts;…」。
- 训练与推理用同一个函数生成注释。训练侧在渲染样本时加(`train/samples.py`),不改数据文件,因为 `transform_synth.py:706` 拒绝非标准的系统消息。
- 注释的 token 数计入最大长度。

**进入时机:**FT3 没有带注释训练过,系统 A 不加注释。注释随 FT4 一起训练、一起检验。系统 B 的「纯模型」成绩指不加注释、不投票、不用规则。

### WP8 A、B 二选一与留出验证(留出集只在这里打一次分)

**依次判定:**
