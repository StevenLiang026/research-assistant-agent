# M7(修订):对比试训选底座 + 思考训练 + 路由兜底,在新测试集 v2 上检验单步与端到端 90%

> 修订版:所有者 2026-10-19 批准。它取代同日先前批准的原版计划;原版见提交 `e13a81a` 中的本文件。

## Context

**为什么修订。**原计划同日获批,随后跑的两道闸门都没过:

| 闸门 | 结果 | 门槛 |
|---|---|---|
| G1 老师够不够强 | v4-pro 手写开发题 42/60,flash 38/60,差 +6.7 pp | ≥ 47/60 且 ≥ +8 pp |
| G2 4B 值不值得换 | Qwen3-4B 第 274 步开发集 107/150(FT2 同步数 100);峰值显存 4.74 GB、449 tok/s | ≥ 108/150 |

**所有者的改判。**
- 原计划规定 G1 不过就停止单步目标。所有者改判为「两项都追,全力提本地准确率」,并要求不回退 1.7B,底座由对比试训决定。
- 目标函数:只追求结果的准确率。时延和迁移工作量都不计,允许思考。

**G1 的另一个发现,导致老师换回 flash。**
- v4-pro 与 flash 在 103 道草拟题上只有 84 道答案一致(81.6%)。
- 现有训练轨迹全部来自 flash。v2 金标准如果用 v4-pro,本地模型会在占 70% 的草拟题上因为风格不同被扣分。
- 所有者因此把老师统一为 flash。

**这次修订的要点:**
1. 老师、v2 金标准、路由兜底一律用 flash。v4-pro 不再使用;WP1 的计价代码保留,不影响别的部分。
2. 底座从 9 个候选里通过对比试训选出。参照点是 G2 的 Qwen3-4B 不思考版,107/150。
3. 本地模型可以思考,训练用老师的思考过程:
   - M2 老师每个回合的 reasoning_content 都在响应缓存 `runs/llm/cache.sqlite` 里,可以逐回合精确取回;
   - 缺口用 flash 补写。
4. 省下的预算用来扩充老师轨迹,约 1.8 倍。提问时我说约 2.3 倍,按 M2 实测的「每条请求约 5.1 次调用、约 72% 被接受」重算后下调。
5. v2 测试集照建:单步 300 题、端到端 150 任务。判据与成本上限不变。

**预期产出:**
- 对比试训结果 `results/bakeoff-m7.json`,以及选出的底座;
- FT3:选中的底座 + 思考训练 + 扩充后的数据;
- 冻结的路由 R3,兜底模型是 flash;
- 预登记后打开 v2 一次,检验两个 90% 目标。

单步能否达到 90% 仍不确定,按实际结果报告;报告中并列手写子集成绩和 FT3 单独的成绩。

## 关键设计

### 1. 模型家族层:新包 `src/research_agent/family/`

**结构**
- `Family` 是静态规格,`LoadedFamily` 是规格加分词器,加载时自检。
- 规格字段:
  - 按模式区分的模板参数与生成提示后缀;
  - 思考块的开头串与收尾串(收尾串即强制收尾时追加的那段);
  - 轮次终止符与停止串;
  - BOS 策略;
  - 工具格式;
  - LoRA 目标;
  - trust_remote_code;
  - 钉住的版本;
  - 解码默认值;
  - 推理预算 R。
- 识别方式:用 `config.json` 的 architectures 加聊天模板 SHA-256 自动识别。`--family` 可以显式指定,但必须与自动识别一致。模板哈希未登记时报错。

**工具格式**
- 协议 `ToolFormat` 有三个方法:render、parse、locate(返回调用名与各参数值的字符区间)。
- 五种实现:
  - `qwen_json`:从现有的 `toolcalls.parse_tool_calls` 与 `agent/route.py` 的 `_blocks`/`_read_call` 迁入;
  - `qwen_xml`;
  - `minicpm_xml`;
  - `glm_kv`;
  - `pythonic`:只用 `ast` 解析字面量,不执行任何代码。
- 后四种格式的标量按 MODEL_TOOLS 的 JSON schema 转换类型,转不了的保留原文。

**BOS 恰好一个**
- 所有路径都用 `add_special_tokens=False` 分词,由模板文本决定有没有 BOS。
- 训练改用预分词数据:`input_ids` + `completion_mask`。这样 TRL 的字符串路径不再参与,它的两个问题随之避开:分词时自动加 BOS,在补全末尾自动补 eos。
- 推理时向 llama-server 发 token id,服务器不再自行加 BOS。
- 每个样本、每个请求都断言 BOS 的个数。

**改动的调用点**
- `train/samples.py`、`llm/local.py`(接受 id 提示与采样字段)、新增的 `llm/generation.py`;
- `agent/context.py`、`agent/models.py`(新增 `LocalModel.for_family`,旧构造器不变)、`agent/route.py`(注入 locate);
- `agent/types.py`(`AssistantTurn` 加 reasoning/thinking 字段,不进入 `to_api`);
- `eval/systems.py`、`eval/runner.py`;
- `scripts/train.py`、`export_adapter.py`、`run_eval.py`、`run_e2e.py`、`select_checkpoint.py`、`run_test.py`、`run_acebench.py`。

接口细节写进 `docs/m7-家族层设计.md`。

### 2. 思考

**更早步骤的思考一律丢弃,训练与推理一致。**理由:
- M2 老师生成轨迹时,也看不到自己更早的思考;
- 上下文长度不变,不会多出超长样本;如果保留,9.4% 的样本会超过 4,096。

只生成、只训练当前这一步的思考。

**按样本选模式**
- 有思考的样本是 THINK 样本:提示用思考模式的生成提示,补全是「思考块 + 答案」。
- 没有思考的样本是 NO_THINK 样本:空思考块放进提示里,不计损失,补全只有答案。模型因此不会学成「输出空思考」。
- THINK 样本超长时退回 NO_THINK,不丢弃,样本数和顺序都保持不变。

**思考数据**
- 存成侧车文件,原数据文件逐字节不变;`ReasoningIndex` 用答案的 SHA-256 校验是否过期。
- `scripts/join_reasoning.py` 处理 synth-m6 的 4,308 个老师回合:
  - 用 `cache.request_key` 加 `context.build_context` 重建缓存键,逐回合取回;
  - 4,141 个非空;
  - 其中 2,814 个与训练答案完全一致,直接使用。
- `scripts/rationalize_reasoning.py` 补写其余约 2,294 个回合:
  - 构成:M6 改过答案的 1,327 个、脚本生成的 800 个、思考为空的 167 个;
  - 调用:`CloudClient`,flash,关思考,`off_peak_only`;
  - 输入上下文和最终答案,要求写出推理:英文,2–6 句,≤ 120 词,不得与答案矛盾;
  - 不合格的重试一次;仍不合格,该样本按 NO_THINK 处理。
- 公开数据的 12,424 个样本保持 NO_THINK。
- 新生成的轨迹由循环直接带出 reasoning,写成同格式的侧车。

**推理:两段生成**
1. 第 1 段最多生成 R 个 token。
2. 如果没有出现 `</think>`,补上收尾串,再生成答案,最多 512 个 token。
3. R 默认 1,024;按训练思考长度的 p99 向上取整到 256 的倍数,上限 2,048。

**解码**
- 会思考的家族用厂商推荐的采样参数。
- 种子由(基种子、提示 id、阶段、样本号)散列得出;第 2 段也带种子,所有采样字段都显式发送。
- 服务器设置为 `-np 1`、`cache_prompt false`。
- 不思考的家族保持贪心。

**评分口径**
- 解析、`content` 和 `no_think_leak` 都只看答案段。
- 思考内容写进 AssistantTurn 与运行记录。

**路由信号**
- 只在答案段上计算:答案第 1 个 token、工具名、各参数值的首个 token、答案段的平均对数概率。
- 另加硬触发 `budget_forced`。
- 阈值在开发集上重新拟合。

**端到端预算**
- 提示门槛保持 4,096 − 256,与 FT2 可比。
- 服务器 `-c 8192`,需满足 ≥ 4,096 + R + 520。
- 每次运行报告有多少步超出了训练长度。

### 3. 训练(`scripts/train.py`)

- **新参数:**
  - `--family`;
  - `--reasoning FILE...`;
  - `--stop-at-step N`:余弦周期仍按全程计算;
  - `--sample-keys`;
  - `--smoke-longest`;
  - `--target-modules`。
- **固定设置:**`loss_type chunked_nll`(只对补全 token 分块算 lm_head,G2 已在用)、`data_seed 42`。
- **最大长度 5,120:**THINK 样本多出的思考也放得下。Qwen 分词下没有任何 NO_THINK 样本超过 4,090,所以 C1 以 4,096 训练时,数据与其他候选相同。
- **回归锚点:**Qwen3 混合家族在 FT2 数据上,新路径生成的 id 与掩码要和旧路径 TRL 的分词逐 token 相同,覆盖全部 17,532 个样本。

### 4. 对比试训

**冒烟 S0–S6**(每个候选都跑,C1 除外,理由见下)

## 风险与对策

**模型与工具链**
- **模板不接受我们的消息形态。**例如原始字符串参数、要求 tool id、schema 缺少 properties。对策:`to_template_messages` 统一规范化;dry run 时计数;问题样本对所有候选一起剔除。
- **标签在服务器输出里消失。**这些标签是特殊 token 时会出现。对策:客户端从 token id 解码,由 S5 检查。
- **LoRA 被 llama.cpp 静默忽略。**新张量可能出现这种情况。对策:用 S6 的随机 LoRA 逐组检验,不过就收窄目标模块。
- **转换器缺口:**
  - 缺 sentencepiece(按需装);
  - Spark 4B 的配置不一定满足转换器的断言;
  - Qwen3.5 的转换默认附带 MTP 层。
- **Qwen3.5 训练慢。**回退实现约 150 tok/s 时,FT3 全程约 60 h。对策:先装内核(已获准);装了仍超过 60 h,判为不具资格。
- **Spark 厂商代码。**可能与 transformers 5.18 不兼容,而且是不受信任的代码。对策:先通读,钉版本,记哈希,离线加载。

**评测与数据**
- **评测噪声。**不同种子之间约差 ±3–4 题。对策:取 3 个种子的均值,并设第 548 步续训规则。
- **确定性。**llama.cpp 的默认种子是随机的。对策:每次请求都发种子,第 2 段也发;采样字段全部显式;`-np 1`。
- **补写思考与真实思考风格不同。**对策:按来源分别报告长度;时间允许时做一个只用真实思考的消融。
- **结果可能不到 90%。**
  - 草拟题占 70%,金标准就是 flash 自己的回答,转交给它即判对;手写题才反映真实难度。
  - 报告时并列手写子集、FT3 单独成绩和路由系统成绩,不把 90% 说成本地模型自身的能力。

**资源与许可**
- **磁盘。**按波次下载;删除淘汰候选的权重前先请你确认。
- **子智能体的用量。**v2 的评审与手写题、各实现工作包都依赖子智能体。对策:分批进行,`effort: medium`,工作流可续跑。
- **许可证。**C9 是 lfm1.0;若它胜出,公开适配器前先核对条款。
- **发热降速。**G2 后段吞吐从 509 降到 377 tok/s。时长一律按降速后的吞吐估算。
