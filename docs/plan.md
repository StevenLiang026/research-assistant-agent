# 科研助理 Agent:函数调用小模型(结对项目计划)

## 背景
- 目标:做一个以大模型为核心、评测可复现的完整项目:一个解决具体问题的应用,其中关键一环换成用 LoRA 微调的开源小模型,配自建评测集与基线对比。
- 设计要能交代清楚三件事:评测集怎么构成、基线是什么、统计口径是什么;Agent 部分覆盖工具调用与稳定 JSON 输出、失败兜底、SFT 数据构造、LoRA 与遗忘、时延与成本。

## 已定(他 10-02 的选择)
应用 + 微调结合;结对(我搭骨架、先写测试,核心模块他亲手写);三个候选里选**候选 2 科研助理 Agent**;每周时数答「一直先做」,按「不设固定周时数、持续推进」理解,里程碑按他本人工时计;API 与云 GPU 合计 **300 元以内**。

## 项目定义
- **用途是他真实的每周阅读**:每周一篇 arXiv 论文的阅读笔记,条目模板固定(来源、日期、类型、与本周所学的关系、约 300 词英文摘要分 Problem/Method/Evidence/Limitations 四段、新术语、待解术语)。Agent 接一句中文或英文需求:检索 arXiv、筛选、读摘要与正文、按这个模板产出条目。
- **摘要留给使用者**:`write_note` 两种模式:`scaffold`(默认:填来源与日期,四段各放原文证据句并标出处,证据句必须是取回正文的原样子串;摘要留给他)与 `draft`(模型代写,只用于评测与演示)。
- **微调对象**:Qwen3-1.7B(纯文本,apache-2.0)的 LoRA 适配器,负责选工具、填参数、输出合法 JSON、判断不该调用;没把握时转交 DeepSeek。
- **说法的边界**:训练轨迹由 deepseek-flash 生成,微调模型是从它蒸馏出来的,所以结论写成「以 X% 的成本接近 flash 的质量」,不写「超过老师」。
- **不做**:多模态、多智能体编排、向量数据库服务化、arXiv 以外的数据源。

## 架构
- **仓库与环境**:本仓库,包名 `research_agent`,uv 管理,Python 3.13(BFCL 依赖的 faiss-cpu 1.11.0 在 Windows 只有到 cp313 的轮子)。**M0 更正**:BFCL 还钉死 numpy 1.26.4 与 tree-sitter 0.21.3,两者 Windows 轮子只到 cp312;S5 用 uv 覆盖 numpy 后在 3.13 上跑通,按原钉法跑需要 Python 3.12,见 `docs/m0-验证.md`。
- **本地推理**:llama.cpp 的 llama-server(Windows CUDA 版)加载 Qwen3-1.7B 的 GGUF 与 LoRA 适配器的 GGUF,启动时挂上适配器但不启用,每个请求用 `lora` 缩放 0 或 1 切换基座与微调版:两者共用同一份权重、量化与服务,去掉一个混杂因素。客户端用训练时同一个 HF 模板渲染提示词,调 `/v1/completions` 并取逐 token 对数概率(路由要用)。
- **云端**:openai SDK 指向 DeepSeek 的 OpenAI 格式接口,密钥只按名读环境变量 `DEEPSEEK_API_KEY`;每个响应按请求内容的 SHA-256 进 SQLite 缓存,重跑不花钱;`budget.py` 按价目上限把用量折成元,超过阶段上限就抛错停下。
- **七个工具**:
  | 工具 | 参数 | 要点 |
  |---|---|---|
  | `search_arxiv` | query、categories(枚举)、date_from、date_to、max_results 1–20、sort_by | 错误码 EMPTY_RESULTS、RATE_LIMITED、UPSTREAM_ERROR |
  | `get_paper` | arxiv_id(正则校验) | NOT_FOUND |
  | `fetch_fulltext` | arxiv_id、section(introduction/method/experiments/conclusion/all)、max_chars | 取 `arxiv.org/html/<id>`;robots.txt 要求间隔 15 s;无 HTML 时降级为摘要 |
  | `search_notes` | query、tags、top_k | SQLite FTS5 的 BM25;语料含已有的阅读笔记条目(只读) |
  | `write_note` | arxiv_id、mode、四段内容、新术语、待解术语 | 按笔记模板渲染成 Markdown,写入项目的 `notes/` |
  | `list_notes` | tag、since、limit | |
  | `ask_clarification` | question、missing(枚举) | 把追问做成工具,追问对不对就能按工具选择来量 |
- **校验与失败策略**:参数先过 JSON Schema,再过语义检查(编号正则、起止日期顺序、不许未来日期、`write_note` 的编号必须在本轮出现过)。输出不合法:把错误信息回给模型修一次,再不行这一步转交 DeepSeek。限流、超时、5xx:3 s、6 s、12 s 退避重试,最多 3 次;arXiv API 全局每 3 秒一次、单连接。无正文降级为摘要并在条目标注;无结果先放宽一次条件再告知用户,绝不编造编号。每轮最多 8 步,同一调用重复 3 次判为死循环。旧的工具输出压缩成编号与标题,训练数据用同一套压缩,训练与推理都控制在 2,048 token 内。
- **置信度路由**:硬触发是解析失败、修复后仍不合法、未知工具;软信号是决策 token(调不调用的首 token、工具名、各参数值首 token)的最小概率,与整段调用的平均对数概率二选一,在开发集上按 AUROC 定。阈值在开发集上扫描,预先登记的规则是「API 调用比例最小,且开发集成功率不低于 flash 减 2 个百分点」,定下后冻结进配置并记开发集哈希。一轮里一旦转交就留在云端。对照组是同调用比例的随机路由与理想路由。

## 微调数据
- **公开数据约 4,000 条**(只进训练):ToolACE 1,500(把 `[func(args)]` 解析成 JSON 调用)、glaive-function-calling-v2 800(约 10% 是不调用的普通对话,防遗忘)、hermes-function-calling-v1 700、glaive_toolcall_zh 500、Deepexi/function-calling-small 500(cc-by-4.0,README 要署名)。统一转成 TRL 的 `{messages, tools}` 格式。
- **领域合成轨迹约 2,400 条**:
  1. 录制:按限速取约 150 次检索、300 条元数据、120 篇 HTML 正文。元数据录像(CC0)进仓库;正文录像只留本机,不公开。
  2. 种子:12 类意图,每类至少 6 个中英文说法模板(他写),配主题、编号、标签的槽位池。
  3. 先切分再生成:每类意图的模板按 4/1/1 分给训练、开发、测试;主题簇与论文编号按 70/15/15 互斥划分。测试题的说法、主题与编号训练时都没见过。
  4. 生成:flash 改写请求,再在回放模式下充当 Agent 产出轨迹。场景配比:正常调用 55%、不该调用 15%、追问 10%、报错后恢复 15%、并行调用 5%。
  5. 校验(他写):每次调用都能解析且合法;执行成功(恢复类除外);最终输出里的每个编号都在本轮工具输出中出现过;日期与分类约束满足;条目字段齐全。拒收率入日志,预计接收 70% 到 75%。
- **去重与防泄漏**:规范化后精确去重;MinHash(5-gram,Jaccard ≥ 0.8)近重复;训练题与任何开发、测试题 Jaccard ≥ 0.6 就删训练题;训练数据与 BFCL、ACEBench 题目做 13-gram 重叠检查;泄漏审计(模板、主题、编号跨切分重叠)必须为 0,否则构建失败。测试集至少 30% 由他从零手写,压低「老师风格」偏差。
- **许可**:DeepSeek 开放平台条款(2026-04-29 生效)第 4.2 条允许用输出训练其他模型(含蒸馏);第 8.1 条要求向终端用户说明内容由 AI 生成,README 照写。

## 训练
- TRL v1.14.1 + PEFT + bitsandbytes 0.50.2 + torch 2.14.1+cu130。非思考模式。`assistant_only_loss=True` 时 TRL 自动换用 Qwen3 训练模板,该模板在每个助手回合都渲染空的思考块,而推理模板只在最后一轮渲染:多步轨迹的训练与推理不一致,第一周先验证(S2)。
- LoRA:r=16、alpha=32、dropout 0.05,作用于 q/k/v/o/gate/up/down。SFTConfig 要点:max_length 2048、不打包、单卡批 1、梯度累积 16、2 轮、学习率 1e-4 余弦、预热 3%、bf16、梯度检查点、seed 42;超过 2,048 token 的样本丢弃不截断,并计数。
- bf16 LoRA 还是 QLoRA 由 S4 的 50 步实测定:峰值显存 ≤ 7.0 GB 用 bf16,否则先降到 1,536,再换 4-bit QLoRA。约 15 万词表的 fp32 logits 是显存大头。
- 时长估计:每轮约 660 万 token,两轮 3 到 6 h;QLoRA 慢 1.3 到 1.6 倍。
- 选检查点看开发集的单题成功率,不看损失。每次运行记录:损失、梯度范数、学习率、tokens/s、峰值显存、丢弃样本数、数据清单 SHA-256、git 提交、完整配置、pip freeze、掩码检查(解码 5 条样本,确认只有助手片段计损失)。
- 导出:基座转 GGUF(Q8_0),适配器用 `convert_lora_to_gguf.py` 转换;100 条开发题对比 HF bf16 与 llama.cpp Q8_0 的结果,差距照实报告。
- 消融(只在开发集):只用公开数据对比混合数据;秩 8 对比 16;去掉不调用、追问、恢复三类样本。

## 评测
- **测试集 300 条**(单步决策,中英各半):工具调用 120、看过工具输出后的下一步 30、不该调用 50、追问 40、报错恢复 40、并行调用 20。**开发集 150 条**同法构造。主指标是单题成功(该题全部检查通过);另报 JSON 合法率、工具选择准确率、参数完全匹配、不该调用的误调率、追问准确率、逐参数 F1。归一规则:字符串 NFKC 并压空白;编号去前缀与版本号;日期 ISO;分类与标签按集合比;取默认值的参数视同未填;自由文本的 query 按「必含词」判对,另报严格匹配。
- **对照系统**(同一服务、非思考、贪心解码):B0 基座、B1 基座加 3 个示例、B2 deepseek-flash、B3 deepseek-v4-pro(上界)、B4 只用公开数据微调;参考行为基座的思考模式;主角是 FT 微调版与 FT+R 微调加路由。
- **通用能力回归**:
  - BFCL V4:Python 3.13 独立环境装固定提交;加一个约 15 行的处理器子类,在提示末尾补空思考块,做非思考对比;BFCL 发不了 `lora` 字段,所以开两个 llama-server 实例,一个不挂适配器、一个挂;用 `--skip-server-setup` 与 `REMOTE_OPENAI_BASE_URL` 指向它们。跑 simple_python、multiple、parallel、parallel_multiple、irrelevance 与 live 系列,不跑要 SerpAPI 的 web_search;多轮与记忆类是可选加项。数字是自测,不是官方排行榜。
  - ACEBench:装时去掉 vllm,打 3 处补丁(vllm 导入加保护、加一个读本地服务地址的分支、登记两个本地模型名),跑 normal 与 special 两类的中英文。它要求 `[ApiName(key='v')]` 文本格式,所以还能测「格式遗忘」:微调版若一直输出 `<tool_call>`,照实报告。
- **端到端**:测试 60 个、开发 20 个任务,他按自己的阅读需求写。在固定日期冻结的录像上回放;每个里程碑另跑一次实时,只看真实性、不做比较。确定性检查:编号无编造(凡符合格式的编号都必须出现在本轮工具输出里)、约束满足、条目字段齐全、scaffold 证据句是正文原样子串;另记步数、工具报错、耗时、token 与每任务成本。
- **故障注入**:超时、空结果、带 Retry-After 的 429、500、截断的 Atom、HTML 404、加 5 s 延迟;注入率 0、0.2、0.5,固定种子;看恢复率、故障下成功率、空结果后的编号编造、对失败接口超过 3 次的重试风暴。对比 FT、B0、B2。
- **路由曲线**:开发集上扫阈值,画单题成功率对 API 调用比例与每百任务成本,含随机与理想路由;冻结的阈值在测试集只用一次;报本地与云端每步时延的 p50、p95。
- **统计**:按题配对 bootstrap(1 万次,固定种子)给差值的 95% 置信区间,并按模板族做聚类 bootstrap 作稳健性检查;McNemar 精确检验;预先登记 4 个主比较(FT 对 B0、FT 对 B1、FT 对 B4、FT+R 对 B2)并做 Holm 校正;分类别结果只描述不检验。
- **测试集锁**:SHA-256 存档;评测脚本只在哈希一致且标明里程碑时才放行,每次访问写日志;全程最多访问 3 次,README 写明次数。检查点、提示词、阈值、解码设置一律只在开发集上定。
- **数字对账**:时延取墙钟与 llama.cpp 返回的 timings;显存每 200 ms 采样;成本按用量乘价目。`build_report.py` 汇总结果;README 里每个结果数字放在标记块内,`check_readme_numbers.py` 逐个核对,不一致就让 pre-commit 失败。

## 验证
- CI(只用 CPU):回放模式下的工具单测、Schema 校验、指标与统计函数、数据流水线;行为测试检查模板族、主题与编号跨切分不重叠,近重复低于阈值,测试集哈希未变。
