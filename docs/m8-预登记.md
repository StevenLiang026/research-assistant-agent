## 校准(B0 与 FT3,先于 FT5)

一台服务器(llama.cpp b11349,`scripts/serve_local.py --model models/Nanbeige4.1-3B-Q8_0.gguf --adapter runs/train/ft3/gguf/checkpoint-1635-f16.gguf -c 8192 -- -np 1`,单槽,挂 FT3 的适配器,B0 以 lora 缩放 0 运行)依次跑开发集 B 的 B0、开发集 B 的 FT3、开发集 A 的 FT3(`scripts/run_special_dev.py`:思考、贪心、$R = 1{,}280$、答案至多 1,200 个 token)。之后的开发集 B 运行(FT5 的候选)用同一条服务器命令。`scripts/calibrate_special_dev.py` 写出 `results/special-dev-calibration-m8.json`;队列在 FT5 开训之前把它与三份记录的 SHA-256 记进日志 `runs/m8/queue/queue.log`,以此为准,进度文档随后补记。

- **K1**:$\mathrm{lenient}^{B}_{\mathrm{B0}} - \mathrm{lenient}^{B}_{\mathrm{FT3}} \ge 0.05$;
- **K2**:在参数值有误的题上,FT3「带着非法值照样调用,或用缺参数的句式代替本题句式」的比例高于 B0;
- **K3**:$\mathrm{zh}^{B}_{\mathrm{FT3}} > \mathrm{zh}^{B}_{\mathrm{B0}}$。

K1 不成立时,PG1 改为 $\mathrm{strict}^{B}_{c} \ge 0.75$;K2、K3 只报告。

## 数据修订(至多一次)

FT5 最后一个检查点 $L$(第 441 步)先在 dev ∪ dev-v2 上跑种子 0(作为选点的一部分),再跑开发集 A;`scripts/check_m8_revision.py` 写出 `results/revision-check-m8.json`。它只对 FT5 当下的最后一个检查点下结论:步数须等于 `runs/train/ft5/result.json` 的步数,GGUF 须与选点文件记录的 SHA-256 一致且不是 FT3 的;各次运行的清单、记录与汇总须与 `decide_m8.py` 同样的核对一致,否则不下结论。下列任一条成立即修订一次数据并重训:

- **R1**:$\mathrm{strict}^{A}_{L} < 0.6$;
- **R2**:$\mathrm{FR}^{A}_{L} - \mathrm{FR}^{A}_{\mathrm{FT3}} \ge 3$;
- **R3**:$S^{\mathrm{dev},0}_{\mathrm{FT3}} - S^{\mathrm{dev},0}_{L} \ge 8$,$S$ 为 `data/eval/dev.jsonl` 上种子 0 的成功数(离线作用运行时规则,归一评分)。

## 选点(`scripts/decide_m8.py`,机械执行)

1. 4 个检查点各在 dev ∪ dev-v2 上跑种子 0、1(`scripts/select_checkpoint.py`,思考,$R = 1{,}280$,归一评分);离线作用运行时规则,两种子之和记 $S_c$,按 $S_c$ 从高到低排序,平手取较晚的一步。最后一个检查点的种子 0 沿用数据修订那一步的运行。
2. 沿排序依次在开发集 B 上运行(只在 `decide_m8.py` 要求下一个时运行),取第一个满足全部门槛的检查点 $c$:
   - **PG1**:$\mathrm{lenient}^{B}_{c} \ge \mathrm{lenient}^{B}_{\mathrm{B0}} + 0.05$(K1 不成立时按上文回退);
   - **PG2**:$\mathrm{strict}^{B}_{c} \ge 0.70$;
   - **PG3**:$\mathrm{FR}^{B}_{c} \le \mathrm{FR}^{B}_{\mathrm{FT3}} + 2$;
   - **PG4**:$\mathrm{exact}^{B}_{c} \ge \mathrm{exact}^{B}_{\mathrm{FT3}} - 0.05$,且 $\mathrm{zh}^{B}_{c} \le \mathrm{zh}^{B}_{\mathrm{FT3}}$。
3. **MG**:$S_c \ge S_{\mathrm{FT3}} - 10 = 475 - 10 = 465$。
4. 满足门槛与 MG 为 GO;没有检查点满足门槛,或选中点不满足 MG,为 NO-GO:不跑 ACEBench,向所有者汇报。

`decide_m8.py` 对每次开发集 B 运行重新评分,并要求全部记录成功、单槽、同一底座文件、同一 llama.cpp 版本与同一家族模板,校准文件与 B0、FT3 的记录逐一对应;结果写入 `results/decision-m8.json`,不覆盖。

## 执行

一个无人值守的队列(仓库外的辅助脚本 `m8_queue.ps1`)在本文提交上的一个独立工作树中依次执行:校准 → FT5 的干跑与训练(检查点须为第 111、222、333、441 步)→ 最后一个检查点的数据修订判断 → 选点 → `decide_m8.py`(开发集 B 按需运行)→ GO 时 ACEBench 与 `acebench_gates.py`。任何一步失败、触发数据修订或 NO-GO 时停下;队列不提交,结果文件由会话提交(提交前重建 `results/numbers.json`)。启动时先核对后面各步要用到的一切,不满足即在几秒内停下,而不是几十小时后才失败:工作树的五个目录联接、所在提交与已跟踪文件无改动、各步要运行或加载的脚本与输入都在该提交中、FT3 的 GGUF、端口与 B0 的 M7 运行相同,并用 FT3 的 GGUF 代替选中点做一次 ACEBench 干跑(不启动模型、不写文件)。

## 事先预测(不作判据)

按 M7 的逐层数字:差距 $-3.96$ = 特殊组 $-2.93$ + 普通组 $-1.03$。若特殊组回到 B0 的水平、普通组收回一半,$\hat\Delta \approx -3.96 + 2.93 + 0.52 \approx -0.5$ 个百分点。对这一假设的信念标准差取 1.3,抽样标准误约 0.95,合成后 $\hat\Delta$ 的 80% 区间约 $[-2.6, +1.6]$。$p_{\mathrm{NI}} < 0.05$ 约需 $\hat\Delta > -2 + 1.645 \times 0.95 \approx -0.43$,通过的概率约 0.5。中文原值照抄与顶层对象缺参的样本只有计划的一半左右,普通组与 incomplete 层的回升可能低于上述假设。

## 与计划的差异

- **数据缺口**:计划的中文原值照抄 250 条只得到 128 条,缺参数中的顶层对象只有 9.5%(中文)与 10.6%(英文),开发集 A 没有中文原值照抄题,中文特殊类由英文记录补足的比例为 42.3%(计划约 30%)。原因是可用的中文记录不够:在去重上限、值必须由请求完整给出、对象整体删除这三条规则下,即使不用私有排除表,中文原值照抄的供给也只有 251 条(需要 278 条)。计划中补足缺口的办法(用 flash 翻译英文请求并锁定参数值,约 1 元)没有执行,以便尽快开训;按现有数据训练,缺口逐条写在上文。
- **私有排除表的排除比例**:数据构造时 Claude Code 设定「任何来源被排除超过 2% 即停下」,有两个来源超过了。保留排除;排除使中文原值照抄的供给从 251 条降到 224 条,但不排除也凑不够(需要 278 条),其他类别的条数不受影响。
- **校准记录的时间**:计划写「开发集的校准结果在训练前写进进度文档」。本文改为队列在开训前把校准文件和三份记录的 SHA-256 写进队列日志,以此为准,进度文档随后补记;写定时间仍早于任何 FT5 分数,显卡不必等会话。
- **数据修订的阈值**:「以上」按含本数写定(上文)。
- **规模**:开发集 A 为 140 题(计划约 150,少的是中文原值照抄的 10 题);ACEBench 函数名按克隆实际计数为 4,241 个(计划写 4,223)。

## 披露

- 数据按 ACEBench 的失败类型设计;训练与选点不用 ACEBench 的题目、句子、调用写法与函数名。
- 续训比从底座重训少一分可比性;超参数在此写定。
- H3 的统计功效有限:即使 FT5 与 B0 真实持平,通过概率也只有约三分之二。
- 本文对「参数值不合法」的认定来自 schema 与描述中的约束,可能与 ACEBench 的出题口径不一致。
- 开发集 B 上中文值改写的判断只有 18 道题,PG4 的中文部分与 K3 的分辨力有限。
